# Windows capture assessment

The Windows Alerts and Reports pages use the same capture analysis as the cross-platform edition. Alerts are prioritized by severity and include capture status, confidence, affected context, source references where available and follow-up checks. PDF and editable Word assessments include selected evidence excerpts. Standalone HTML and structured JSON additionally include the full indexed command sections, which can contain configuration values and credentials.

| Evidence to compare | How it helps trace an issue | What remains uncertain |
| --- | --- | --- |
| Physical link transitions, interface state, cumulative CRC and an observed CDP neighbor | Identifies the affected interface and where to check the other end. A matching down/up pair is shown as retained history. | Event count is bounded by log retention. CRC does not identify the failing cable, optic or endpoint. A second sample establishes whether the counter is increasing. |
| Err-disabled port status, err-disabled reason table and syslog violations | Connects an err-disabled interface to its explicit trigger (`bpduguard`, `storm-control`, `psecure-violation`, `loopback`) and timestamped syslog events. | Underlying physical or endpoint cause on the connected segment requires verification before re-enabling the port. |
| EtherChannel member flags, spanning-tree root ports, VLANs and observed neighbors | Shows which local VLAN root paths depend on a bundle with a member or state worth checking. | Intended standby membership and downstream reachability require confirmation. |
| Trunk native VLANs, switchport negotiation and VLAN database state | Identifies active trunks using default Native VLAN 1, access ports assigned to suspended or unconfigured VLANs, and ports with DTP negotiation enabled. | Peer switch VLAN/trunk configuration and intended segmentation policy require verification. |
| PoE inline port operational state, module power budgets and `%ILPOWER` logs | Surfaces `faulty` or `power-deny` PoE endpoints and modules with `<10%` remaining PoE budget headroom. | Endpoint hardware health and physical cabling require inspection on site. |
| Stack member states and stack-port link/sync health | Highlights non-Ready stack members (`V-Mismatch`, `Provisioned`) and degraded stack cable links (`Link OK: No`, `Sync OK: No`, `In Loopback: Yes`). | Physical stack cable seating or planned member provisioning requires confirmation. |
| Control-plane and management security controls (`show running-config`, `show install summary`) | Audits explicit AAA model state, VTY Telnet exposure, HTTP server state, reversible/legacy passwords, default/RW SNMP communities, CoPP, and uncommitted software packages (`U`/`D`). | Out-of-band management network controls and site-specific security exceptions are outside a single capture. |
| Crash artifacts, data corruption, facility alarms, buffer failures and ASIC TCAM utilization | Flags retained crashinfo/core dumps, memory corruption records, active facility alarms, packet buffer allocation failures, and hardware TCAM slices exceeding 80%/95%. | Historical counters and retained files require correlation with reload timestamps and a second sample to confirm ongoing pressure. |
| Clock events, NTP status and syslog timestamp settings | Helps distinguish events recorded before clock synchronization from later events. | Unsynchronized timestamps and logs without years cannot establish a reliable incident sequence. |
| Smart Licensing communication errors, reporting endpoint, ACK and DNS output | Points to a licensing transport or name-resolution investigation. | Reporting failure alone does not establish a forwarding outage or license enforcement. |
| Abnormal reload history, last reload reason and crash artifacts | Points to the incident window and the logs or external power records to compare. | A generic power/unknown reload reason cannot establish a power failure. |

Network Health Reporter checks visible when supported output exists include err-disabled ports, connected half-duplex links, stack half-ring state, power supply state, BPDU Guard configuration, VTP role, inactive static routes and recent reloads. Configuration review findings are informational or warning based on exposure. Platform environment and resource findings use the state reported by the device. A single capture cannot provide fleet topology, wireless coverage or historical trends without additional captures.
